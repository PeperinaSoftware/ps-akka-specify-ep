# Implementation Plan: Flight Training Scheduler

**Branch**: `main` | **Date**: 2026-04-23 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-flight-training-scheduler/spec.md`

## Summary

Implement six Akka SDK component stubs for a flight training scheduling system: `BookingSlotEntity`, `FlightConditionsAgent`, `ParticipantSlotEntity`, `ParticipantSlotsView`, `SlotToParticipantConsumer`, and `FlightEndpoint`. Domain objects (`Timeslot`, `BookingEvent`, `Participant`) are provided and must not be modified. The implementation follows a strict event-driven flow where bookings fan out 3 events (one per participant type), propagated by a consumer to per-participant entities, queryable via a view.

## Implementation Order

The implementation must follow this dependency order:

```
1. BookingSlotEntity        ← no dependencies
2. FlightConditionsAgent    ← no dependencies
3. ParticipantSlotEntity    ← no dependencies
4. ParticipantSlotsView     ← depends on ParticipantSlotEntity events
5. SlotToParticipantConsumer ← depends on BookingSlotEntity + ParticipantSlotEntity
6. FlightEndpoint           ← depends on all above
```

## Component Implementation Notes

### 1. BookingSlotEntity

Key points:
- `markSlotAvailable`: emit `ParticipantMarkedAvailable(entityId, cmd.participant().id(), cmd.participant().participantType())`
- `unmarkSlotAvailable`: emit `ParticipantUnmarkedAvailable(...)`
- `bookSlot`: validate `currentState().isBookable(...)`, emit 3 `ParticipantBooked` events (student, aircraft, instructor) via `effects().persist(List.of(e1, e2, e3))`
- `cancelBooking(String bookingId)`: validate booking exists via `findBooking`, emit 3 `ParticipantCanceled` events for each booking entry
- `getSlot()`: `effects().reply(currentState())`
- `applyEvent`: switch on event → delegate to domain methods `reserve`, `unreserve`, `book`, `cancelBooking`

### 2. FlightConditionsAgent

Key points:
- SYSTEM_MESSAGE: include VFR criteria (visibility ≥ 3 sm, ceiling ≥ 1000 ft AGL, wind ≤ 25 kt, no thunderstorms), instruct model to call `getWeatherForecast` tool, and return JSON `{"timeSlotId": "...", "meetsRequirements": true/false}`
- `getWeatherForecast`: parse day from slotId (position 8-9 after splitting on `-`); day == 13 → return below-VFR conditions; else → return good VFR conditions
- `query`: pass `timeSlotId` in `userMessage()`

### 3. ParticipantSlotEntity

Key points:
- Add `emptyState()` returning `null`
- Each command handler persists corresponding event and replies `Done.done()`
- `applyEvent`: switch → `MarkedAvailable` → `State(..., "available")`, `UnmarkedAvailable` → `State(..., "available")` (or keep existing), `Booked` → `State(..., bookingId, "booked")`, `Canceled` → `State(..., bookingId, "canceled")`

### 4. ParticipantSlotsView

Key points:
- `onEvent` switch: `MarkedAvailable` → `updateRow(new SlotRow(..., null, "available"))`, `UnmarkedAvailable` → `updateRow(rowState().withStatus("available"))` or `deleteRow()`, `Booked` → `updateRow(new SlotRow(..., bookingId, "booked"))`, `Canceled` → `updateRow(rowState().withStatus("canceled"))`
- Add `@Query("SELECT * AS slots FROM participant_slots_view WHERE participantId = :participantId AND status = :status")` to `getSlotsByParticipantAndStatus`
- Note: `SlotRow` is a plain record, no `with*` methods — create new instances

### 5. SlotToParticipantConsumer

Key points:
- Switch on `BookingEvent` type
- For each type, derive entity key via `participantSlotId(event)`, then call correct `ParticipantSlotEntity` command via `componentClient.forEventSourcedEntity(ParticipantSlotEntity.class).call(...).invoke(...)`
- Return `effects().done()` after the invoke (fire-and-forget via consumer)

### 6. FlightEndpoint

Key points:
- `markAvailable`: call `BookingSlotEntity.markSlotAvailable` with `Participant`
- `unmarkAvailable`: call `BookingSlotEntity.unmarkSlotAvailable`
- `createBooking`:
  1. Parse slotId → `LocalDateTime`, reject if not in future (400)
  2. Call `FlightConditionsAgent.query(slotId)` with a fresh UUID session
  3. Reject if `!report.meetsRequirements()` (400)
  4. Call `BookingSlotEntity.bookSlot`
  5. Return `HttpResponses.created()`
- `cancelBooking`: call `BookingSlotEntity.cancelBooking(bookingId)`
- `getSlot`: call `BookingSlotEntity.getSlot()`
- `slotsByStatus`: call `ParticipantSlotsView.getSlotsByParticipantAndStatus(new ParticipantStatusInput(participantId, status))`
